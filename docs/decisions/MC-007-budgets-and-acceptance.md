# MC-007 — Budgets and measurable mesh acceptance

Evidence state: specified; worksheet calculations are not simulator, radio or battery results. This decision refines the [MC-006 base wire contract](MC-006-wire-contract.md) without changing its bytes. [Scenario definitions and checks](../../tests/simulator/scenarios/README.md) make the arithmetic and future gates reproducible.

The subsequent [MC-008 contract](MC-008-crypto-contract.md) specifies maximum387-byte encrypted CHAT, eight-unit cold receive work and one71-byte LINK_PROOF frame per direction (two proof work units per endpoint). These fit this worksheet's deliberately larger1024-byte/eight-unit item and initial eight-frame/eight-unit proof reservations. The reservations below remain conservative placeholders, not executed valid crypto/proof vectors; MC-020/022 must supply implementation evidence. No periodic proof-renewal traffic is assumed.

## Accounting and admission

All byte limits use octets; KiB=1024 bytes and MiB=1024 KiB. Every native GATT value attempt counts as one frame and its complete value length, including the four-byte outer header and any fragment/type envelope. Count retries and origin sends separately, but charge them too. A logical multicast to three links consumes three separately framed transmissions. Do not call that one radio send. Count actual native attempts even if the native call fails; reserve tokens before calling, and do not refund attempted sends.

Use monotonic time and fixed-point token buckets, initially full once per process. At elapsed t, tokens=min(capacity, previous+rate*t); a charge succeeds only if every applicable bucket can pay, then subtract atomically. No partial debit on rejected admission. An interval of length T admits at most capacity+rate*T. These are burst/refill bounds, not sliding-window counts. A backwards clock never adds tokens. Restart is not a security boundary: the process-wide bound applies within each runtime; OS/native intake must also remain bounded.

Incoming values first face a 512-byte native staging bound and per-link/node frame+byte charges, even if malformed. Oversized arrays are discarded before copying; charge their reported byte length with saturating arithmetic and one frame, which normally rejects. Counters for drops are saturating, fixed-size. Resource allocation, reassembly, claimed-sender tables, validation and crypto follow admission. There is no over-budget display path.

| Resource | Per-link capacity / refill | Node capacity / refill |
|---|---|---|
| Ingress frames |15 / 1 per second|60 / 8 per second|
| Ingress complete-value bytes |24 KiB / 2 KiB per second|64 KiB / 8 KiB per second|
| Egress frames, every class |15 / 1 per second|60 / 8 per second|
| Egress complete-value bytes |24 KiB / 2 KiB per second|64 KiB / 8 KiB per second|
| Cryptographic work units |20 / 20 per second|40 / 40 per second|
| Unknown logical types |5 / 1 per 5 seconds|20 / 1 per second|
| New SYNC sessions, each serving/requesting role separately |1 / 1 per 60 seconds|2 / 1 per 30 seconds|
| New native connection attempts |3 / 1 per 20 seconds per observed address|6 / 1 per 10 seconds|

Each signature verification, signature creation, DH operation and AEAD open/seal costs one crypto unit; each candidate recipient-key/tag derivation also costs one before work. A credential plus message needs two verifications unless the identical validated credential is cached. Actual failures and embedded SYNC work cost the same. Multi-step operations reserve their known full cost; no partially verified result becomes trusted. MC-008 must enumerate the final construction's exact operation count before implementation. Allow at most two concurrent crypto jobs; queue limits below still apply. This bounds counts, not CPU milliseconds: benchmarks must record operation timings on the eventual devices.

Reconnects create fresh scoped fragment/session state, but never refill node buckets or retained address admission buckets. Native addresses and HELLO keys are not a physical-person identity. Address rotation can bypass only the address bucket; the node bucket and active-link cap remain. Keep address rate records 5 minutes, at most 256/32 KiB; when full reject admission for new addresses until expiry. Link ingress allowance is replaced on reconnect; the total attacker bound therefore includes node ingress, node connection admission and all admitted attacker links, never just one link's quota. Do not use unproved HELLO keys to inherit trusted state.

Normal Android admits at most six total links, iOS four, Saver three, Android phone Beacon eight, including links still handshaking. These are memory/work ceilings, not claims that native hardware can hold that many. HELLO deadline is 10 seconds; MC-008 proof gets a separate 10-second deadline after HELLO if attempted. Missing proof leaves unverified traffic only where the MC-006 policy permits it. Global link/queue budgets survive policy transitions; clamp token capacity down on a downgrade without granting new credit on an upgrade.

## Logical rates, forwarding and fairness

Per-sender CHAT buckets are shared across all arrival links and all channels in each class: General+Confessions capacity 5/refill 1/12 s; ordinary Event Updates 2/1/30 s; structurally organizer-signed Event Updates 10/1/6 s; private CHAT 15/1/4 s. All CHAT also consumes a sender-wide 20/1/3 s bucket. This preserves the existing structural organizer allowance without granting a badge; invalid signatures remain untrusted. REACTION uses a separate 30/1/2 s sender bucket. Sender spoofing/rotation remains bounded only by link/node admission. At sender-table capacity, do not evict an active sender to grant a fresh full bucket: reject new sender entries until 300 seconds of inactivity frees one. Existing entries never refill merely because packets are invalid.

ANNOUNCE is link-local, capacity 2/refill 1/30 s; send immediately after admission then every 30 s Normal/Beacon or 60 s Saver. Coalesce queued announcements to the newest one. SYNC_REQ initial admission uses session buckets; a valid continuation is not a new session but still consumes every frame/byte/work allowance. CRED_REQ capacity 1/refill 1/5 s per link; at most two retries 5 s apart per missing credential. EVENT_INFO and CRED_OFFER each use capacity 2/refill 1/30 s per link in addition to aggregate admission. Unknown types use their dedicated buckets, never a known type's allowance. A repeated exact accepted logical packet can be dropped cheaply after frame accounting; no new crypto or relay work follows it.

Normal forwarding+served-SYNC uses a node bucket of 120 frames/refill 2 per second; Saver 40/refill 2 per 3 seconds. Count every egress fragment, including SYNC markers. Own packets, HELLO, ANNOUNCE and requested SYNC controls still use aggregate egress buckets, but not this forwarding bucket. Phone Beacon has no additional mode-specific forwarding bucket; it still obeys the finite aggregate egress/frame/byte/crypto/session/memory limits. This resolves the old ambiguous packets/minute unit without exempting beacons from spam controls. Lack of forwarding credit cannot undo valid local acceptance, but lack of ingress credit always prevents it.

An egress scheduler must shape transmission to no faster than one frame per second per link (no catch-up burst after backpressure), within all other budgets. This conservative default fits the receiver's sustained ingress allowance; increasing throughput requires a reviewed joint budget change and physical evidence. Scheduling ticks may occur more often, but do not imply extra GATT sends. Once an object starts, send its fragments contiguously in index order; at most 16 frames before native retries. Backpressure pauses service, never causes unlimited buffering. Abort an unfinished object 30 seconds after its first native attempt, with an explicit local failure; the deadline never resets on progress/retry. Native frame/readiness timeouts may fail it sooner. This bounds in-flight lifetime as well as pre-start queue waiting.

At object boundaries, five classes participate: link controls, own traffic, forwarded CHAT/control/unknown, forwarded REACTION, and served SYNC/ANNOUNCE. Use frame-cost deficit round robin with respective quanta 8, 16, 8, 4, 8; deficits cap 32 and idle classes reset to 0. Within the last class, alternate ready SYNC objects and ANNOUNCE so neither starves. Charge an object's full frame cost from its class deficit before starting. Urgent disconnect is local teardown, not an unbudgeted wire packet. The chosen quanta prioritize own traffic and CHAT while giving every nonempty class service. Under global contention rotate eligible links in stable round robin; never promise a latency bound while native readiness or admission credit is absent.

Native retries also debit that class's deficit and all actual-attempt buckets. The existing driver policy permits at most one retry per failed frame, so at most 16 additional deficit units can accrue for one object; retire this bounded debt before starting the class's next object. Do not refund attempted work on failure. Initial frame reservation is scheduling credit, not permission to skip the per-attempt work checks.

Hold-off remains 80–400 ms Normal, 40–150 ms tier 3, 300–700 ms tier 0, 10–40 ms Beacon, sampled by the scenario's deterministic random stream. A packet needs both its hold-off and scheduler turn. Suppression is only per egress with evidence that that peer holds it; absence of evidence forces forwarding when budgets allow. Since coverage already cancels an egress, the old residual probability table adds no further v1 thinning. An advisory digest may have false positives: test their cost separately, never call them delivery proof. Local power limits may still shed forwards, including on a bridge; reachability tests declare a workload below those limits.

## Bounded state

Limits include keys, metadata, indices, allocator capacity and retained payloads; implementations must account reserved capacity, not just payload length. A shared allocation counts once globally but each per-link reference counts against its link's entry cap. The core exposes current/peak reservations for adversarial tests. Fixed native queues must reserve from these ceilings before copying across FFI. Total transient protocol state must stay below 8 MiB Normal/Saver and 32 MiB Beacon; process/library overhead and encrypted persistent DB are measured separately, not claimed inside that arena.

SYNC snapshots hold only at most 5000 cache sequence references, not another payload copy. Missing/evicted references are skipped. Stream one response object at a time per served walk, so later page items do not expire waiting behind the whole page. At global cap, reject a new session before snapshot allocation. Outbound full handling evicts oldest unstarted forwarded REACTION, then unknown/control/CHAT, then served SYNC (abort walk if evicted); coalescible ANNOUNCE has one slot. Never evict an in-flight object's remaining fragments or an admitted own object. If that leaves no capacity, reject the new object. All objects have finite wait/readiness deadlines and explicit local failure status; admitted does not mean delivered.

The sender table can hold the node ingress maximum of 60 + 8*300 = 2460 newly observed one-frame senders over its five-minute idle window, without assuming a single claimed identity per physical peer. Larger active state still meets the fixed cap or refuses admission; never allocate on an over-budget attempt. Accepted variants are searched across source partitions for cheap exact dedup. Keep at most eight partitions, each with at most 512 entries; a disconnected partition may retain entries until age expiry but can be reclaimed oldest-retired-first to admit a new link. Never reclaim another live peer's partition for a new peer. Disconnect frees fragment, queue and session state, not a fresh grant of node work allowance or an authentication-freshness claim.

Persistent friend pins, adopted roots, history and settings are MC-018's separate encrypted-store schema and caps. Network traffic cannot create a friend pin or adopted root. Reserve at most 128 loaded friend records/128 KiB and 16 loaded adopted roots/16 KiB for active protocol use; if UI import would exceed this capacity, require an explicit user removal rather than silent replacement. MC-018 must account its disk/index sizes without expanding these live protocol ceilings silently.

## SYNC workload and feasibility

One session serves at most 8 data items and 8192 encoded logical bytes, whichever first; at most 4 items per page. Encoded bytes include logical headers, signatures, crypto padding and ciphertext. Framing/markers are charged additionally. Stop before an item that would cross the limit and emit the explicit budget-ended marker if more candidates remain. Newest-first selection examines the bounded snapshot, skips Bloom matches and eviction, and never assumes the requester's channel subscriptions. The requester filter represents its at-most 5000 eligible held CHAT IDs; reject item_count>5000. False positives are counted as omissions, not repaired by reusing a fixed filter.

The predeclared test target is 100% of the at-most 8-item/8192-byte selected non-Bloom-matching set plus the terminal marker, within 120 s of the initial request's first frame, on one lossless ready Normal link at C=146. Test both directions simultaneously. Use max-size 1024-byte synthetic logical envelopes for capacity accounting; actual signed 556-byte and final encrypted vectors replace synthetic sizing cases when their owning tickets implement them. Each side also sends a signed 421-byte ANNOUNCE at 0, 30, 60, 90 s and one clear 36-byte REACTION every 10 s. Initial HELLO and a reserved 8-frame proof allowance are accounted in setup before initial request; proof syntax/work remains MC-008 and cannot be fabricated as valid traffic.

The worksheet executes a feasible paced trace, not only division of total bytes by refill. Per direction: 64 data frames, 2 marker frames, 10 request frames for the reverse walk, 16 ANNOUNCE frames and 12 reaction frames total 104 frames during the 120-second session window. Full-value bytes are `8*(1035+8*16)+2*16+2*(546+5*18)+4*(421+4*18)+12*40 = 13,060`. Setup costs one 59-byte HELLO plus eight reserved frames at 146 bytes each, totaling nine frames/1,227 bytes. Reserve up to eight crypto units per received test item, one per incoming ANNOUNCE signature and one per outgoing ANNOUNCE signature; MC-008 must supply exact counts and revise this worksheet before implementation if a supported case exceeds that envelope. Setup reserves eight units per direction for the still-unfrozen proof. The maximum admitted test operation bundle fits the 20-unit link/40-unit node bursts. Maximal byte/frame assumptions do not imply a valid 1024-byte organizer record exists.

Continuations may start immediately after ordered page completion; they have no new session token charge. The session deadline, gaps and cumulative item/byte counts never reset. No ACK/retransmission extension is invented: loss or backpressure may cause partial results and timeout. Completion means all earlier sequences processed, not delivery receipt. Under concurrency or attack, keep all bounds and report partial progress; this named single-link gate is not a whole-cache replication promise.

## Simulator and physical gates

Machine-readable scenario definitions and worksheet live under tests/simulator/scenarios. They define seeds, exact overlay edges/capacities, traffic and pass thresholds. MC-012 implements the event runner using the real core; MC-007 validates the definitions and budget arithmetic only.

Metrics: denominator is every scheduled logical origin and every graph-reachable recipient under original TTL 7 (distance 1–7), excluding origin. Report admission refusals separately; never remove them from the scheduled workload denominator. Unique receive ratio counts each pair once. Latency is first validated receive minus scheduled origin time; undelivered pairs count as failures, with p95 reported only alongside delivery ratio. GATT metrics split origin/relay/SYNC/control, attempts/successes/retries, frames/bytes, and per-egress link. Byte accounting excludes unknown on-air BLE overhead, which needs physical traces. Suppression ratio divides actual forwarded GATT attempts by the same seed/topology/workload run with hold-off and per-egress suppression disabled; all admission/TTL/queues/loss remain identical. Report both delivery and cost; denominator 0 means not applicable.

Use seeds 7, 19, 43. Each deterministic loss decision uses SHA-256(seed, domain, link, object, fragment, attempt) with explicitly encoded fields in the scenario format; topology, hold-off and traffic use separate domains. No platform PRNG dependence. Capacity 146 both directions; 20 ms native completion/transit delay and readiness always true unless a case specifies otherwise. Establish links before traffic and isolate live-only tests from SYNC. State exact simulator phase initialization, including empty caches/full buckets and initial ANNOUNCE.

Live suite: a 10-node path, an 8-node cycle, two 4-node cliques joined by a single edge, the same pair joined through one degree-two bridge, and a K6 dense graph. Each runs 360 seconds with 12 maximum-size clear CHATs, one every 30 seconds, origin cycling ascending node ID, unique senders; zero loss/churn. Require 100% TTL-reachable delivery and p95 ≤ 30 seconds; path endpoints beyond seven edges must receive zero live copies from that origin. K6 requires suppression ratio ≤ 1.00 and delivery 100%; bridge cases compare baseline and require no lost reachable pairs. Report the actual reduction, including zero: a three-fragment transfer paced at one frame/second can outlast the 400ms hold-off, so there is no support for a universal positive reduction target on fresh traffic. This applies the ticket's stated fallback to preserve reachable delivery rather than force an unsupported relay ratio; it does not weaken ingress or claim an energy benefit. A Saver/tier-zero bridge uses the same low workload and must preserve delivery. Include per-node relay budget peaks.

Stress suite: same graphs/seeds, 20% independent per-frame loss, and deterministic bridge outage[120, 180) seconds. Keep the static TTL-reachable scheduled-pair denominator and additionally report the outage-affected cohort; do not exclude failed traffic or require impossible full delivery without retransmission. Require no resource cap violation, no false session completion, no relaying TTL 0, and deterministic trace equality on rerun. A separate post-reconnect SYNC selected-set gate uses the lossless workload above; stale cursors/responses must never bind the new link.

Additional cases: empty/8-item/9-item SYNC, mixed channels with known and absent subscriptions, fixed Bloom false positive retained on retry, cache insertion/eviction between pages, zero-length markers, reordered/conflicting/gapped sequences, C145 refusal/C146 acceptance/C182/C512 counts, rotating sender IDs, 8 attacker links/reconnects, rejected first fragment at expiry, credential/key/orphan/queue floods, exact invalid-first/valid-later variants, reserved/unknown-type TTLs. All abuse cases run 600 s and assert every cap plus no rejected-frame display, no unverified trust and no encrypted-to-clear fallback; they make no success-rate promise under deliberate flooding.

Physical gates remain MC-025/027/038. Predeclare paired 4-hour screen-off runs after 15 min warm-up, fixed brightness for separately reported screen-on runs, battery start 60–90%, ambient 20–25°C, same health/OS/build/radio configuration, three repetitions per mode/device with idle-app control, randomized run order. Report raw battery percentage-point slope/hour, incremental slope vs control, energy when instrumentation supports it, held/discovered links, GATT frames/bytes and delivery. Targets: Normal≤ 5 percentage points/hour, Saver≤ 2, iOS held-background≤ 2; require the physical link's named delivery gate too so a suspended non-relaying app cannot pass on drain alone. Beacon plugged-power runs report energy and traffic; unplugged auto-downgrade at 30% remains mandatory, with no invented universal 8–15% claim. Failure blocks the corresponding gate pending diagnosis and explicit threshold/scope decision. Simulator send reductions never count as measured battery savings.
