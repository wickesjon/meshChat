# MC-011 channel, link and display contract

`channels.tsv` commits all 8,000 positional triples and the three public channels. `generate.py` independently reads the normative slot table and computes SHA-256 with Python; it fails on any collision, including a private/public collision. The Rust tests compare every ID and glyph and round-trip both supported private join URL forms. Slot order follows the design, never UI sorting. NFC → trim → lowercase → collapsed whitespace precedes channel name recognition. Unknown positional words are update-needed errors; arbitrary unknown strings are never hashed into joined channels.

Public glyphs are wave, fire and lightning-bolt. The v1 private mapping interprets the already-hashed four-byte channel ID as an unsigned big-endian integer modulo the fixed nine-entry pool (moon, sun, star, mushroom, crystal, spiral, comet, cactus, disco-ball). This makes the design's hash-mod-pool wording concrete without another hash or platform endian dependence. These are stable icon identifiers, not attacker-controlled Unicode glyphs. The v1 pool and slot order are fixed in code and vectors.

`public-links.tsv` adds 30 independently encoded public friend/event URL cases. These contain synthetic public bytes and deliberately unverified signatures, never trusted identities. `true` means only an inert structural proposal. Percent-encoded reserved characters in display segments are valid (e.g. `%3D` is a literal `=`); raw reserved characters reject. Splitting occurs before decoding, and decoded percent signs/separators cannot trigger another route parse. Binary segments require canonical unpadded base64url with zero unused bits; charset, encoded-length and residual-bit checks imply exact re-encoding equality. Friend/event bundle length/version checks grant no pin or root authority. Event root IDs derive from the full root public bytes, not from the unsigned display name.

All parser results are `UnconfirmedProposal`. There is no mutation API, native UI callback, network navigation or automatic import. Native integration must show the relevant confirmation sheet, then perform key/DH binding, signatures, root/credential validity and protected import under their owning security tickets. Friend/event names remain original, unsigned display claims; native presentation must use `text::display` for a safe separate rendering. Staff credential labels pass display-character validation. Staff proposals retain the decoded seed only in zeroizing storage with a consuming transfer to a future protected importer; proposals deliberately have no Debug, Clone or serialization implementation. Caller-owned URL/QR buffers must also be cleared. Tests synthesize staff seed input at runtime, use zeroizing URL/seed buffers, never use it as an identity and never print/persist it. Errors contain no input substring.

Text processing pins NFC and TR39 confusable tables to Unicode 16.0.0. Wire byte limits remain 20 nickname, 280 message, 32 event name and 16 credential label bytes, with an empty label permitted. C0/C1 controls, the design's bidi ranges and U+200B–U+200D/U+FEFF reject; this deliberately rejects ZWJ emoji sequences under the existing design, while ordinary emoji remain valid within UTF-8 byte limits. Display conversion counts decomposed combining marks, drops leading orphan marks and retains at most two per base, then composes NFC. This prevents precomposed accents bypassing the combining-mark cap. Original authenticated bytes are borrowed and never modified. Outgoing editors recheck the transformed byte count, rejecting expansion beyond the wire budget rather than truncating bytes.

Nickname display additionally removes the specified badge glyphs and case-insensitive ASCII staff/official substrings, repeating after removal and normalizing away newly orphaned marks. A stripped-empty nickname displays `unnamed`. U+2028/U+2029 become spaces in nickname presentation. `single_line_ellipsis` explicitly requires native widget line/width clamping; this core cannot measure pixels and does not claim a native rendering test. TR39 skeleton equality against the sanitized local nickname produces only a warning. Skeletons are not displayed, used as keys, or treated as identity proof. Native widgets must render message text inertly, without markup or auto-linkification, and keep verified badges in separate chrome.

Inputs are bounded before allocations: channel normalization ≤128 UTF-8 bytes, links ≤2,048 ASCII bytes, binary decoding into fixed 130/32-byte buffers, display segment output capped at its decoded byte limit, and text normalization at its wire bound. No fallback widens those bounds or weakens Unicode checks. The mutation target uses seed `0x4d433031315f7631`, 100,000 byte mutations of valid/invalid public links and Unicode cases, inputs up to 2,049 bytes, both valid and invalid UTF-8, normalization/output-bound assertions and preservation of original bytes. It is reproducible mutation fuzzing, not coverage-guided or native evidence.

Run from the repo root:

```
python -B tests/vectors/channels/generate.py
cargo test --test links --test links_fuzz --locked
cargo test --test links --test links_fuzz --locked --release
```

Host tests and dependency checks do not satisfy the required native-consumer checks for this dependency change. Android/iOS integration and independent security/physical gates remain separate.
